### 修改前遇到的问题或缺陷

#### 问题 1：项目此前仅有 Web/桌面端，移动端用户无法在微信内发起问诊、查看报告与档案

**解决方法：**
新建 Taro 小程序，复用既有后端 REST / SSE 接口，把核心问诊流程原样搬到移动端。消息以 `ChatMessage` 模型承载（`role` / `content` / `streaming` 等），通过 `services/sse.ts` 消费 `reply` / `thinking` / `end` / `report` 等事件实现流式输出；`services/medical.ts`、`auth.ts` 分别封装问诊会话与登录鉴权；`pages/consult` 串联阶段指示（`StageIndicator`）与聊天气泡（`ChatBubble`）完成一轮问诊。

#### 问题 2：SSE 长连接与报告状态轮询在页面卸载/会话结束时未清理，会在后台持续计时、重复请求，造成连接与内存泄漏

**解决方法：**
在 `pages/consult/index.tsx` 中抽取 `clearPoll()` 函数，并在 `useEffect` 的 cleanup 以及会话结束、重置、出错等多处流程出口调用，确保轮询定时器随页面生命周期回收；`services/sse.ts` 内置 `clearWatchdog()` 看门狗定时器，在连接关闭或出错时统一清理，避免悬挂的计时器持续触发。二者均不在正常流程外额外加守卫，仅在必要出口统一收口。

#### 问题 3：微信开发者工具编译/预览时残留大量 `wechatdevtools` 进程，达到系统打开文件上限（EMFILE: too many open files），导致编译超时、内置服务 500

**解决方法：**
联调前在任务管理器中结束全部 `wechatdevtools` 进程后重开开发者工具，仅保留一个项目窗口。`dist/` 产物仅数十个文件，确认该报错与业务代码无关，是开发者工具自身进程泄漏所致，非代码缺陷。

#### 问题 4：真机/模拟器控制台偶发 `TypeError: Cannot read property '__subPageFrameEndTime__' of null`

**解决方法：**
判定为基础库 3.17.3 灰度版本自身的 bug——调用栈全部位于 `WAServiceMainContext.js` 的 `setInterval` 回调中，无任何业务文件参与，目标页面采样时该内部性能字段为 `null` 被读取。处理方式是切到稳定版基础库 / 升级开发者工具 / 清除缓存即可消除；该报错仅打印红字、不影响任何功能，无需改业务代码。

## v1.1.0 — ReAct 推理可解释性 + 前端去 AI 化（2026-09-30，commit `9b7cc5a`）

### 版本号与迭代更新概述

接入后端已上线的 ReAct 推理分步能力（SSE `step` 事件 + `GET /api/sessions/{id}/steps` 历史回放），新增推理过程可视化组件，让小程序端能展示"模型在想什么、调了什么工具、引用了哪篇资料"；同时对聊天气泡与问诊/登录核心页面做去 AI 化、自然化样式改造。本次提交改动 `miniapp/` 下 10 个文件、+913 / −28 行。

### 该版本小程序的具体修改内容

- **新增组件 `components/ReasoningSteps/`**：`index.tsx`（181 行）+ `index.module.scss`（238 行）。推理步骤时间线（可折叠），含步骤类型映射（💭思考 / ⚡动作 / 🔍观察 / ✅作答 / ⚠️降级 / ℹ️说明 + 图标）、引用列表 `[n]`、句子级溯源、脏数据过滤封装 `ReasoningStepsSafe`、按 `seq` 排序、耗时统计。
- **`components/ChatBubble`**：`index.tsx` +37、`index.module.scss` +25——去 AI 化气泡样式与排版。
- **`pages/consult`**：`index.tsx` +115、`index.module.scss` +25——接入 `ReasoningSteps`（实时流式累积与历史回放共用 `ChatMessage.steps` 字段），并去 AI 化。
- **`pages/login`**：`index.tsx` +127、`index.module.scss` +99——去 AI 化登录页。
- **`services/medical.ts`** +23：新增 `getSessionSteps(sessionId, turnIndex?)`，调用 `/api/sessions/{id}/steps`（对 404 使用 `quietStatuses` 静默处理），透传推理数据。
- **`types/index.ts`** +71：新增 `ReactStep` / `ReactStepRef` / `ReactSentence` / `ReactTraceTurn` / `SessionStepsResult`；`ChatMessage` 增加 `steps` 与 `stepsMissingReason`；`SSEEvent.event` 联合体增加 `step`。

### 修改前遇到的问题或缺陷

#### 问题 1：后端已支持 ReAct 分步推理并以 SSE `step` 事件增量下发，但小程序端此前只能展示最终回答，用户看不到中间推理过程，可解释性与可信度不足

**解决方法：**
建立后端—前端契约，复用 `ChatMessage.steps` 字段承载推理步骤，实时流式累积与历史回放（`getSessionSteps`）共用同一字段。新增 `ReasoningSteps` 组件，按 `seq` 渲染思考/动作/观察/作答等步骤，支持折叠、耗时统计与引用列表；引入句子级溯源（`ReactSentence`）：终答按句切开后逐句绑定 `[n]` 引用，未引用的句子标注"通用表述，无直接知识来源"而非丢弃内容；引用编号 `[n]` 仅在 `kind=kb` 的知识片段上占用，避免与记忆/就诊记录的个人史编号撞车造成错误归因。

#### 问题 2：当整轮会话都没有推理步骤（未开启推理、会话早于功能上线、指定轮无记录）时，实现容易退化成"暂无推理过程"之类的空态文案，掩盖真实原因

**解决方法：**
约定后端返回 `missing_reason` 字段说明具体原因，前端通过 `ChatMessage.stepsMissingReason` 必须原样展示该原因，禁止用空态文案替代；组件侧只要 `steps` 非空就完整渲染推理过程，空态交由外层 `stepsMissingReason` 兜底，确保"为什么没有"对用户透明。

#### 问题 3：后端下发的步骤可能因版本差异出现未知 `type` 或 `undefined`，直接渲染会把整块推理 UI 打崩

**解决方法：**
提供 `ReasoningStepsSafe` 封装，在渲染前过滤掉 `type` 不在已知集合（`thought` / `action` / `observation` / `final` / `fallback` / `note`）内的步骤；未知类型一律不显示，避免界面出现未知块或整块崩溃。

#### 问题 4：早期聊天气泡与核心页面带有明显"AI 模板"观感（统一色块、机械排版、强对比配色），与产品"去 AI 化、自然化"定位不符

**解决方法：**
重写 `ChatBubble` / `consult` / `login` 的 scss，气泡统一纯白底、弱化色块、采用更克制的字号、间距与浅色调配色，使对话与表单更贴近自然阅读体验，消息气泡排版保持纯白底、无色块渲染。
