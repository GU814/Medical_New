# 语音识别 & 图片识别 集成说明

> 在现有问诊流程基础上，新增两类易用性输入：🎤 语音输入（语音→文本）、🖼️ 图片输入（图片→信息）。
> 两项功能**不另起交互范式**，而是把识别结果作为「文本输入」接入既有的 `/api/chat` SSE 问诊流程。

---

## 1. 功能定位

| 能力 | 输入 | 处理 | 输出落地 |
| --- | --- | --- | --- |
| 语音识别 (ASR) | 录音文件 (mp3/wav/m4a/amr/pcm) | OpenAI 兼容 `/v1/audio/transcriptions` | 转写文本 → 复用问诊 |
| 图片识别 (Vision) | 图片文件 (jpg/png/webp/bmp/gif) | 多模态 chat（image_url） | 提取信息文本 → 复用问诊 |

识别出的文本会像用户打字一样进入 5 阶段问诊状态机，前端在用户气泡中展示「🎤 语音输入」或「🖼️ 图片」缩略图 + 识别文本。

---

## 2. 后端改动

### 2.1 新增配置（`config.py`）
默认**关闭**，不影响现有行为；本地联调时在 `.env` 按需开启。

```ini
# 语音识别
ASR_ENABLED=false
ASR_MODEL=whisper                 # Ollama: ollama pull whisper; OpenAI: whisper-1
ASR_API_BASE_URL=                # 默认复用 API_BASE_URL
ASR_API_KEY=                     # 默认复用 API_KEY
ASR_MAX_SIZE_MB=10
ASR_SUPPORTED_FORMATS=mp3,wav,m4a,amr,pcm

# 图片识别
VISION_ENABLED=false
VISION_MODEL=llava                # Ollama: ollama pull llava(或 qwen2.5vl); OpenAI: gpt-4o-mini
VISION_API_BASE_URL=
VISION_API_KEY=
VISION_MAX_SIZE_MB=10
VISION_MAX_TOKENS=1500
VISION_SUPPORTED_FORMATS=jpg,jpeg,png,webp,bmp,gif
```

### 2.2 新增文件
- `app/services/asr_service.py` —— `transcribe(audio_bytes, filename) -> str`
- `app/services/vision_service.py` —— `recognize(image_bytes, filename, prompt=None) -> str`
- `app/routers/multimodal.py` —— 路由实现

### 2.3 路由与鉴权
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/asr` | `multipart/form-data`，字段名 `audio` |
| POST | `/api/vision` | `multipart/form-data`，字段名 `image`，可选 query `?prompt=` |

- 鉴权：与 `/api/chat` 一致，需 `Authorization: Bearer <token>`（`AuthMiddleware` 仅放行白名单路径，本路由需登录）。
- 中间件只读取 Header、不消费请求体，multipart 上传安全。

### 2.4 错误码与边界
| 状态码 | 触发场景 | 前端提示建议 |
| --- | --- | --- |
| 401 | 未登录 / token 失效 | 跳转登录 |
| 400 | 文件为空 / 格式不支持 | 提示重录或换格式 |
| 413 | 超过大小上限 (`*_MAX_SIZE_MB`) | 提示文件过大 |
| 422 | 识别结果为空（听不清/看不清） | 提示重试或改用文字 |
| 501 | 功能未启用 (`*_ENABLED=false`) | 提示"功能未开启" |
| 502 | 底层识别服务失败（模型未拉取/网络异常） | 提示服务不可用 |

> 重要：未启用时服务返回 **501 + 明确文案**（指明需 `ollama pull whisper` / `llava`），便于排障，而不是直接崩溃。

## 3. 前端改动

### 3.1 新增文件
- `miniapp/src/services/multimodal.ts` —— `recognizeSpeech(filePath)` / `recognizeImage(filePath, prompt?)`，封装 `Taro.uploadFile`，兼容后端 `{ detail }` 错误协议与断连/超时提示。

### 3.2 修改文件
- `miniapp/src/types/index.ts` —— `ChatMessage` 增加 `imageUrl?`、`fromMultimodal?: 'voice' | 'image'`。
- `miniapp/src/components/ChatBubble/index.tsx` + `.scss` —— 用户气泡渲染图片缩略图与「语音/图片」角标。
- `miniapp/src/pages/consult/index.tsx` + `.scss` —— 输入栏新增 🎤 / 🖼️ 按钮，新增录音与选择图片逻辑，并把识别结果通过 `runChatTurn()` 接入现有 SSE 问诊（与文字发送共用同一流式管线）。

### 3.3 交互流程
1. **语音**：点 🎤 → `getRecorderManager().start({format:'mp3', sampleRate:16000, encodeBitRate:24000})` → 再次点（或到达 60s）→ `stop()` → `onStop` 拿到 `tempFilePath` → 上传 `/api/asr` → 识别文本作为用户输入发送。
2. **图片**：点 🖼️ → `chooseMedia({mediaType:['image']})` → 拿到 `tempFilePath` → 上传 `/api/vision` → 识别文本 + 缩略图作为用户输入发送。
3. 录音 / 上传期间，`发送` 与 `🖼️` 按钮禁用，避免并发。

### 3.4 边界与错误处理（前端）
- 麦克风权限被拒：`onError` 提示「请允许麦克风权限后重试」。
- 取消选择图片 / 拒绝相册权限：`chooseMedia` 抛错 → 静默返回，不打扰。
- 识别失败 / 超时 / 断连：toast 展示后端 `detail` 或「无法连接后端服务，请先启动后端」。
- 识别结果为空：提示「未识别到内容，请重试或用文字」。
- 会话未完成 / 正在发送时：禁用入口按钮，保持交互一致。

## 4. 本地启用步骤

```bash
# 1. 拉取模型(Ollama 本地)
ollama pull whisper     # 语音
ollama pull llava       # 图片(或 qwen2.5vl)

# 2. 在 .env 开启(项目已附默认值)
ASR_ENABLED=true
VISION_ENABLED=true

# 3. 启动后端(小程序模式)
DESKTOP_MODE=false uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000
# 或双击项目根目录 start-api.bat

# 4. 重新编译小程序
cd miniapp && npm run build:weapp
# 微信开发者工具导入 miniapp/dist 预览
```

> OpenAI 兼容模式（非 Ollama）：将 `ASR_API_BASE_URL` / `VISION_API_BASE_URL` 指向对应服务，
> `ASR_MODEL=whisper-1`，`VISION_MODEL=gpt-4o-mini`，并填入 `ASR_API_KEY` / `VISION_API_KEY`。

## 6. 设计取舍
- **复用而非新建问诊分支**：识别结果统一转为「文本输入」，5 阶段状态机、知识库检索、长记忆、报告生成全部自然生效，零重复逻辑。
- **可插拔模型**：ASR / Vision 各自独立配置地址、模型、密钥，可指向 Ollama 本地模型或云 API，互不影响。
- **Fail-soft**：未配置时明确 501 而非静默失败；单条识别失败不影响正在进行的问诊。
